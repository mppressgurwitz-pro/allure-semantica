## Ключевые ловушки (важно для масштабирования)

1. **Кириллица в vendorCode**. Буквы Р/О/В/М/Т/С/Е/Н/К/А визуально неотличимы от P/O/B/M/T/C/E/H/K/A. Скрипт уже auto-нормализует. На потоке 120 SKU обязательно проверять.
2. **Bootstrap.gs onOpen конфликт**. В bound-скрипте копии уже есть `onOpen`. Мой код использует `onOpenSeo_()` и вызывается из конца существующего `onOpen` строкой `try { onOpenSeo_(); } catch(err) {}`.
3. **Script Properties могут хранить чужой ключ**. `getApiKey()` приоритизирует константу над Properties — намеренно.
4. **WB textSearch не всегда находит карточку**. Реализован fallback: полный обход аккаунта (`fetchCardByVendorCode_safe`).
5. **WB API регулярно лежит**. 500-ки бывают по часу. Проверять https://status-seller.wildberries.ru/.

## Что ещё не доделано

- `flattenCard()` не маппит ряд полей: Торговое наименование, ИКПУ, Код упаковки, Тип доставки, NTIN, Высота/Ширина предмета. Нужно посмотреть реальный JSON ответ WB.
- Документационные строки колонки A (типа «Блок для скрипта выгрузки в WB...») попадают в notFound — нужен фильтр.
- Декларации/сертификаты/СГР — отдельный endpoint `/content/v2/get/permits/list`, не подтягиваются.

## Архитектурный выбор (для новой сессии)

Два пути масштабирования, выбирать в зависимости от ответов выше:

**Путь A — отдельная копия Sheet на каждый SKU (текущая модель).**
- Создаём 120 копий из мастера.
- В каждой копии autorun PULL → autorun transferSEO → autorun PUSH.
- Координатор: один master-скрипт, который проходит по списку spreadsheet id и в каждом дёргает функции.
- Плюс: изоляция, легко откатить одну карточку.
- Минус: 120 spreadsheet-ов на Drive, ~370 МБ.

**Путь B — единый dashboard-лист на 120 SKU.**
- Один Google Sheet с 120 строками: vendorCode, Title, Описание, ключевые характеристики.
- Скрипт читает строки по очереди, для каждой делает PULL/merge/PUSH.
- Плюс: всё в одном месте, легко мониторить прогресс.
- Минус: теряется текущая модель «per-SKU копия», требует миграции SEO-контента в плоскую таблицу.

**Моя рекомендация:** Путь A, если SEO-черновики уже лежат в копиях (тогда мы их не пересобираем). Путь B, если SEO-черновики ещё генерируются — тогда сразу плоская модель.
