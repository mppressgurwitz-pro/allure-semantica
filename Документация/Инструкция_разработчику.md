# Инструкция разработчику — установка и сопровождение

## Архитектура

Скрипт — **container-bound** Apps Script, привязанный к конкретной Google Sheets-таблице
`https://docs.google.com/spreadsheets/d/1kLejFBMXdu5MQy9CadL8kNTPoNzKbkDAp0Rqf-jGGkk/`.

Файлы:

```
AppsScript/
├── appsscript.json     # манифест: scopes + Drive API v3
├── 00_Config.gs        # все параметры/константы + чтение _Config листа
├── 01_Main.gs          # onOpen, меню, runFullPipeline, rerunLastFile
├── 02_UI.gs            # сайдбар upload, серверные эндпоинты
├── 03_Importer.gs      # чтение конвертированной XLSX → wbReport
├── 04_Mapper.gs        # вставка raw данных в 3 жёлтые вкладки
├── 05_Cleaner.gs       # нормализация + стоп-слова + min_frequency
├── 06_Semantics.gs     # SemanticCore + Missing Keywords
├── 07_Scoring.gs       # формула скоринга
├── 08_Dashboard.gs     # KPI-панель _Dashboard
├── 09_Logger.gs        # журнал _Logs
├── 10_Validator.gs     # валидация структуры файла
├── 11_KeywordsRaw.gs   # архив _KeywordsRaw + повторное использование
├── 99_Setup.gs         # создание служебных листов
└── Sidebar.html        # форма загрузки файла
```

## Установка с нуля (5 минут)

### Вариант A — через UI Apps Script

1. Откройте таблицу: `https://docs.google.com/spreadsheets/d/1kLejFBMXdu5MQy9CadL8kNTPoNzKbkDAp0Rqf-jGGkk/`
2. **Расширения → Apps Script**.
3. Удалите дефолтный `Code.gs`.
4. Создайте файлы по списку выше:
   - В редакторе: ➕ → **Скрипт** → введите имя (например, `00_Config`) → вставьте содержимое.
   - Для `Sidebar.html`: ➕ → **HTML** → имя `Sidebar` → вставьте.
5. Откройте `appsscript.json` (значок шестерёнки → «Показывать файл манифеста») и замените содержимое.
6. **Службы → +** → найдите **Google Drive API** → выберите версию **v3** → идентификатор `Drive` → Добавить.
7. Запустите функцию `setupServiceSheets` (выберите её в выпадашке наверху → ▶️). Появится диалог авторизации — пропустите все экраны, разрешите доступ к Sheets и Drive. После — таблица заполнится служебными листами.
8. Запустите функцию `installTriggers` — это поставит триггер `onOpen`, чтобы меню появлялось автоматически.
9. Закройте и снова откройте таблицу — увидите меню **🤖 Конкурентный анализ**.

### Вариант B — через `clasp` (CLI)

```bash
npm install -g @google/clasp
clasp login
cd "Автоматизация Семантика/AppsScript"
clasp create --type sheets --rootDir . --parentId 1kLejFBMXdu5MQy9CadL8kNTPoNzKbkDAp0Rqf-jGGkk
clasp push -f
```

Затем в UI Apps Script выполните пп. 6–9 из варианта A.

## OAuth-разрешения

Скрипт запросит при первом запуске:

- `spreadsheets` — чтение/запись текущей таблицы.
- `drive` / `drive.file` — загрузка XLSX и конвертация в Google Sheets через Drive API v3.
- `script.container.ui` — отрисовка сайдбара.
- `script.scriptapp` — установка триггера `onOpen`.

## Триггеры

- `onOpen(simple)` — простой триггер, ставится автоматически контейнером, отвечает за меню.
  Если перестал работать — запустите вручную `installTriggers()` (создаст явный installable trigger).

Дополнительно можно повесить:
- **Time-driven** — например, ежедневный health-check (`rerunLastFile`).
- **On change of folder** — если планируете автозабор XLSX из конкретной Drive-папки.
  Под это используйте `Drive.Files.list` + `modifiedTime > lastSyncTime`.

## Параметры пайплайна

Хранятся в листе `_Config`. Изменение значений не требует деплоя.
Дефолты лежат в `CONFIG.DEFAULTS` в `00_Config.gs` — на случай если параметр в `_Config` пуст.

## Защитные механизмы

- **Идемпотентность.** `setupServiceSheets()` безопасно вызывать многократно.
- **Не ломаем шаблон.** `pasteZaprosy_` не трогает строку 1 жёлтой вкладки, если там уже есть данные/формулы. `pastePokazateli_` пишет только с колонки C, оставляя A и B (там обычно лейблы строк) нетронутыми.
- **Сохранение типов.** Артикулы пишутся как строки (`String(sku)`), чтобы Sheets не съел ведущие нули.
- **Лог-журнал.** Всё пишется в `_Logs`, обрезается до `MAX_LOG_ROWS = 500`.
- **Восстановление.** `_KeywordsRaw` хранит нормализованные данные последнего запуска — можно пересчитать дашборд/скоринг/missing без перезагрузки файла.

## Тонкие места при отладке

- **Drive API не сконвертировал файл** — обычно из-за повреждённого XLSX. Скачайте файл заново, переоткройте/пересохраните в Excel.
- **Время выполнения > 6 минут** — лимит Apps Script. При семядре > 50 000 запросов разбейте по партициям. Не должно случаться при обычном WB-отчёте, размер обычно <2 000 запросов на SKU.
- **Имена листов WB обрезаны до 31 символа** — учтено через `findStartsWith()`. Если WB поменяет нейминг — проверьте `CONFIG.WB_SHEETS`.
- **Пустые строки в `_KeywordsRaw`** — проверьте `MIN_FREQUENCY` в `_Config`, возможно слишком высокий порог.

## План развития

1. Подключить вкладки MarketGuru (`Кластеры`, `Полки`) — добавить в `Importer` логику чтения отдельного XLSX от MG.
2. Веб-парсер WB-выдачи (через Apps Script `UrlFetchApp` + регулярки на `__INITIAL_STATE__` JSON) — для автоподбора артикулов конкурентов.
3. История изменений семядра (snapshot per run) → линейный график размера ядра по неделям.
4. Web-app endpoint `doPost` для приёма XLSX через REST (например, из 1С).

## Версионирование

Семвер в `CONFIG.VERSION`. При значимых изменениях — bump и описание в `CHANGELOG.md` (создаётся при необходимости).
