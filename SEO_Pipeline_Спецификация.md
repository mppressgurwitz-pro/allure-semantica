# Спецификация SEO-pipeline под WB-совместимый формат

Эта спека для того, кто ведёт промпт Claude, генерирующий `_Advice_Last_Raw` / SEO-черновик для каждого SKU.
Цель: чтобы заголовки полей в верхнем SEO-блоке совпадали с реальными именами WB API. Тогда кнопка «🪄 SEO → Перенести SEO → тех.блок» переносит данные 1:1 без словаря-переводчика, и масштабирование на 60+ SKU и 14 категорий проходит без правок кода.

---

## 1. Якоря, которые должны быть в SEO-черновике

В колонке A листа `_Advice_SEO_Draft` обязательны строки-маркеры (без них парсер не найдёт данные):

| Якорь в колонке A | Что под ним |
|---|---|
| `Title (NN/60)` или `Title` | Следующая непустая строка в колонке A = текст Title карточки WB. |
| `Описание` | Следующая непустая строка в колонке A = текст Описания (можно многострочный текст в одной ячейке). |
| `Характеристики` | Ниже — таблица пар «имя характеристики (A) | значение (B)», до пустой строки или следующего якоря. |
| `Main keywords` | Список ключей. Парсер пока не использует, но оставлять для аналитики. |
| `Long-tail` | То же. |
| `📸 Фото-слайды` | Таблица слайдов. Парсер не трогает. |
| `Заметки` | Свободный текст. Парсер не трогает. |

Якоря должны быть **в колонке A**, а не B или C. Регистр учитывается мягко (Title и title — одинаково), но русские якоря пишем как в таблице.

---

## 2. Имена характеристик — строго WB-совместимые

В таблице после якоря «Характеристики» используем **точные имена характеристик из WB API**. Список имён для каждой категории берётся из листа `_WB_Char_Dict` (колонка с названием категории = 1).

### Категория «Пилинг» (12 полей):
- `Вид пилинга` (а не «Тип средства»)
- `Действие`
- `Комплектация`
- `Назначение косметического средства` (а не «Назначение»)
- `Объем товара` (а не «Объём»)
- `Особенности косметики` (а не «Эффект»)
- `Срок годности`
- `Страна производства`
- `Торговое наименование`
- `Упаковка`
- `Форма упаковки`
- `Формат пилинга`

### Категория «Шампуни» (примерный набор — уточняем по `_WB_Char_Dict`):
- `Действие`, `Назначение косметического средства`, `Объем товара`, `Особенности косметики`, `Срок годности`, `Страна производства`, `Тип волос`, `Торговое наименование`, `Упаковка`, `Форма упаковки`, …

### Категория «Духи» / «Парфюмерная вода»:
- `Аромат`, `Группа аромата`, `Назначение аромата`, `Объем товара`, `Особенности косметики`, `Срок годности`, …

(Полный список — `_WB_Char_Dict` в любой копии-Вариант-B, колонка соответствующей категории).

---

## 3. Чего НЕ должно быть в характеристиках

Старый pipeline генерировал имена, которых **в WB API не существует**:
- ❌ `Тип средства`
- ❌ `Пол`
- ❌ `Объём` (правильно: `Объем товара`)
- ❌ `Тип волос` (для категорий, где этого поля нет — например, «Пилинг»)
- ❌ `Тип кожи головы`
- ❌ `Эффект` (правильно: `Особенности косметики`)
- ❌ `Назначение` (правильно: `Назначение косметического средства`)
- ❌ `Активные компоненты` (нет в WB как отдельное поле — растворяется в Описании)

Если категория SKU не содержит характеристику «Пол» или «Тип волос» — **их не нужно генерировать в SEO-черновик вовсе**, даже как комментарий. Они только мешают.

---

## 4. Что добавляется/уточняется в промпт Claude'а

Минимальный патч промпта:

> Сгенерируй SEO-черновик для SKU категории {category}.
> Перечень полей-характеристик бери строго из следующего списка (это реальные имена WB API для категории {category}):
> {список_полей_категории_из_WB_Char_Dict}.
>
> Не используй имена «Тип средства», «Пол», «Объём», «Эффект», «Назначение», «Активные компоненты» — они не существуют в WB API.
> Для «Объёма» используй «Объем товара». Для «Эффекта» — «Особенности косметики». И т. д.
>
> Структура черновика (обязательная):
> ```
> Title (NN/60)
> <текст до 60 символов>
>
> Описание
> <многоабзацный текст 3000+ символов>
>
> Характеристики
> <Имя WB-поля 1>	<значение>
> <Имя WB-поля 2>	<значение>
> ...
>
> Main keywords
> <список>
>
> Long-tail
> <список>
> ```

---

## 5. Что делает кнопка «🪄 SEO → Перенести SEO → тех.блок»

1. Читает верхний SEO-черновик в листе `_Advice_SEO_Draft`.
2. Находит Title и Описание по якорям, переносит в строки технического блока «Title (наименование)» и «Описание» → колонка C «Новое значение».
3. Парсит таблицу «Характеристики». Для каждой пары:
   - Если имя совпадает с WB-именем в тех.блоке → переносит значение в колонку C.
   - Если не совпадает, но есть в маппинге `FIELD_MAP_BY_CATEGORY[категория]` → переносит по маппингу.
   - Если ни то, ни другое — выводит предупреждение «не сопоставилось» с именем поля. Маша заполняет руками.
4. После выполнения промпт SEO-pipeline переписан по этой спеке — все характеристики сопоставляются автоматически, маппинг становится не нужен.

---

## 6. Тиражирование на остальные SKU

Когда Маша подтвердит, что pipeline работает на копии B:
1. Открыть скрипт `Apps_Script_Шаг3_добавить_SEO_тексты.gs`.
2. В константе `TARGET_SHEET_ID` поставить ID следующей копии.
3. В константе `SKU_VALUES` поставить артикул, наименование, категорию следующего SKU.
4. В константе `PILING_CHARS` подставить набор характеристик соответствующей категории из `_WB_Char_Dict` (строки, где в колонке этой категории стоит 1).
5. Запустить `main`.
6. В копию SKU так же вставить bound-скрипт `Apps_Script_Меню_копии_B.gs` через Расширения → Apps Script, обновить категорийный маппинг в `FIELD_MAP_BY_CATEGORY` для новой категории.

После переписывания SEO-pipeline под WB-имена (раздел 4) ручной работы на тиражирование почти не остаётся — для нового SKU достаточно сменить TARGET_SHEET_ID, SKU_VALUES и PILING_CHARS. Я могу автоматизировать и это: написать «мастер-раскатку» — скрипт, который проходит по списку из {id → артикул → категория} и выполняет Шаг 3 для каждой копии. Дайте знать, когда дойдём до этой стадии.
